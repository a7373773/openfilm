## 1. 方法与运行环境

### 1.1 管线

1. 模型：<code>Xenova/clip-vit-base-patch32</code>（CLIP ViT-B/32，ONNX int8 量化，153 MB），从 **hf-mirror.com** 用 curl 预下载到 <code>work/vision/cache/</code>，**运行时零网络**。
2. 解码与预处理：<code>jpeg-js</code> 解码 JPEG → 双线性缩放到短边 224 → 中心裁剪 224×224 → (x−mean)/std（CLIP 官方均值/方差）→ float32 CHW。**完全不依赖 sharp**。
3. 提示词集成（prompt ensembling）：每一类用 2~5 条英文描述句，各自取文本嵌入后**平均再归一化**，避免单句提示词导致的概率平坦。
4. 主标签组（5 类，14 条提示词）：<code>landscape</code> 风景 / <code>hand</code> 手挡镜头 / <code>fabric</code> 衣物包遮挡 / <code>blurry</code> 模糊黑暗不可读 / <code>ground</code> 地面墙面贴脸。
5. 场景标签组（9 类，18 条提示词）：mountain / water / forest / sunset / road / city / snow / beach / night。
6. **p_blocked 定义（按 lead 要求）**：<code>max(p_hand, p_fabric, p_closeup)</code>，**不含 p_blurry** —— 避免雾天/逆光的正常风景被误判。tags.json 同时保留 p_blurry 供单独参考。
7. 辅助信号组（4 类，9 条提示词，<code>aux.json</code>）：clear_scenery 有细节的清晰风景 / empty_sky 纯天空 / washed 过曝洗白低对比 / obstruction 手衣物模糊遮挡。用途是识别"p_landscape 高但其实是过曝天空"的假阳性。
8. 独立客观统计（<code>pixstats.json</code>，Python+numpy/Pillow）：亮度、对比度、Laplacian 方差（锐度）、边缘密度、色彩丰富度、饱和度、暗部/亮部占比、肤色占比、顶/底半区亮度与纹理、天空占比、植被占比、平坦块占比。用于交叉校验与排序辅助。

### 1.2 环境踩坑（供复现）

- <code>npm i @xenova/transformers@2.17.2</code> 直接失败：依赖 <code>sharp</code> 的 postinstall 要去 **github.com** 下 libvips（超时）。解决：<code>npm i --ignore-scripts --no-audit --no-fund</code>，并把 <code>node_modules/sharp</code> 替换成 stub（sharp 会被 @xenova/transformers 顶层 require，但我们的路径完全不用它）。
- hf-mirror 的 **HEAD 请求会偶发失败**，GET 正常；transformers.js 内部 fetch 无重试，所以改成 curl <code>--retry 3 --retry-all-errors -C -</code> 预下载模型（config.json / preprocessor_config.json / tokenizer.json / tokenizer_config.json / special_tokens_map.json / vocab.json / merges.txt / onnx/model_quantized.onnx），再设 <code>env.allowRemoteModels=false; env.allowLocalModels=true; env.localModelPath=缓存目录</code>。
- <code>onnxruntime-node@1.14.0</code> 的 win32-x64 原生库**随 npm 包自带**，无需额外下载，Node v24 下 napi-v3 正常加载。

## 6. 候选区间（纯风景段）

### 6.1 入选规则（lead 指定）

- 连续 ≥3 秒；
- 该区间 mean p_landscape ≥ **该文件自身 p_landscape 中位数 + 0.10**（相对口径，避免绝对阈值失效）；

## 7. 局限与不确定度（必读）

1. **没人能直接看图**，所有结论来自 CLIP + 客观像素统计两条独立证据链，两者方向一致（见 2.2），但都不是"人眼确认"。凡本报告标 ⚠ 的位置，建议剪辑师抽 1~2 帧肉眼扫一下再决定。
2. **p_landscape 绝对分偏低且偏向"亮、平、天空多"**：与 skyfrac 相关 +0.47、与 lapvar 相关 −0.19。所以"p_landscape 高"≈"构图像风景且不暗"，不等于"画面好看/清晰"。因此本报告所有取舍都优先用**文件内相对分位 + detail_score**，并把疑似纯天空单独标出。
3. **p_blocked 口径敏感度极大**（720s vs 86s）：这批素材里"镜头朝下拍地面"占比很高，朝下镜头在语义上既像"地面贴脸"也像"路面风景"。road 场景的帧里只有 3% 的 p_closeup>0.35，说明模型没有把"道路风景"大面积误判成"地面贴脸"，但**边界段的判定仍可能有 ±1~2 秒抖动**。
4. **t 是 1-based**（sec_0001.jpg = t 1）。与 metrics.json 的 0-based t 对齐：t_metrics = t_tags − 1。区间 [start_t, end_t] 含首尾。
5. 量化 int8 模型 + 480px 低分辨率帧：概率分辨率有限，不要解读小数点后第三位。相对排序可靠，绝对值仅供大致参考。
6. 24 个文件里有 8 个短片段（REC-0004/0013/0014/0016/0019/0022/0023/0027），样本少，其"文件内中位数"统计噪声更大。
